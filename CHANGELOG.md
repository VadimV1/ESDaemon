# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/), and versions follow [Semantic Versioning](https://semver.org/).

## [0.1.1] — 2026-10-29

### Added
- **macOS installer package (`.pkg`) for MDM.** Each release now also ships `ESDaemon-<version>.pkg` (and its `.sha256`), so a fleet can deploy ESDaemon with an MDM (Jamf, Kandji, Intune) — which pushes `.pkg`s, not `curl … | sudo bash` — or install one Mac by hand with `sudo installer -pkg ESDaemon-<version>.pkg -target /`. The package is a thin wrapper around `install.sh`: its payload stages the install sources under an opaque directory and its `postinstall` runs the unchanged `install.sh` and removes the staging directory, so a `.pkg` install is byte-for-byte the same as a script install — it keeps a tuned config, ad-hoc signs and verifies the binary and checks its architecture, and loads both LaunchDaemons — and `esdaemon reload` / `uninstall` behave identically (uninstall also `pkgutil --forget`s the `com.esdaemon.pkg` receipt). Built with `bin/mkpkg.sh` (`make pkg`); it bundles the prebuilt universal binary, so the target Mac needs no Swift toolchain. The `.pkg` is unsigned today (fine for MDM, the trust anchor on managed devices); Developer ID Installer signing and notarization, for which `mkpkg.sh` already has a hook (`ESDAEMON_PKG_SIGN_ID`), is the planned step for manual installs. See [README](README.md) / [docs/GETTING-STARTED.md](docs/GETTING-STARTED.md) and [SECURITY.md](SECURITY.md#the-pkg-installer-mdm).
- **`esdaemon` control command** (installed as `/usr/local/ESDaemon/bin/esdaemon`, and on `PATH` as `/usr/local/bin/esdaemon` when only root can write there): `status`, `reload`, `update`, `logs`, `config`, `version`, and `uninstall [--purge]`. Uninstall is now part of the install itself — `sudo esdaemon uninstall` stops and removes both daemons, the install tree and the command itself, so nothing is left on disk and no separate script needs to be kept. `./uninstall.sh` still works and removes the same things itself, without running the installed command.
- **Records carry their event's number, `GlobalSeqNum`.** In the default `sysmon+extras` format every record now has the number EndpointSecurity gave its event (`global_seq_num`, which `slim` and `raw` already kept), right after `UtcTime`; plain `sysmon` keeps Sysmon's fields only. The `esd_filter_error` marker carries it in every format, and an `esd_record_too_large` marker keeps the number of the record it replaces. It puts a Mac's records in order, shows which ones the collector delivered twice, and finds the records on either side of an `eslogger_scoped_gap`. It starts over when eslogger restarts, after an `eslogger_scoped_restart` record. It is not a loss counter: every event the filter leaves out uses up a number, so records skip numbers all the time; records lost in transit after ESDaemon wrote them are caught at the collector tier, not in-band. See [docs/CONFIG.md](docs/CONFIG.md#event-numbers).
- **The install and update trust model is documented.** A new *Supply chain trust model* section in [SECURITY.md](SECURITY.md) states what installing or updating trusts: the supported `curl … | sudo bash` runs as root from this repository, fetches a `main`-or-tag source tarball that is not hash-pinned, and checks the release binary against a checksum from the same release — transit integrity, not authenticity; the binary is ad-hoc signed and not notarized, and `esdaemon update` follows the same path. It adds fleet guidance (pin a revision, verify the checksum out of band, or deploy from an internal copy) and records Developer ID signing and notarization as planned, not promised. README and GETTING-STARTED link to it from the installer one-liner. (Documentation only.)

### Removed
- **Heartbeat.** ESDaemon no longer emits an `eslogger_scoped_heartbeat` liveness record (`EventID` 100 in the `sysmon` formats), and the `[settings] heartbeat` setting is gone — `heartbeat = …` in a config is now rejected as an unknown setting. The record shared the subsystem, category and process of real event records, so it entered the same stream a collector parses as endpoint events and had to be special-cased downstream. Pipeline liveness belongs at the collection tier instead: alert at the collector/SIEM when a host sends no events for N minutes (a log-source-health alert), which covers every log source the same way. See [docs/CONFIG.md](docs/CONFIG.md#pipeline-liveness).
- **Stale pre-rename writer files.** Deleted `src/uls-writer.swift`, the writer from before it was renamed to `ESDaemon.swift` — an older, simpler copy that predates the current writer's heartbeat support and that nothing builds or installs — and `docs/VISIBILITY.md`, an older unlinked copy of [docs/history/keep-rule-design.md](docs/history/keep-rule-design.md) that still described that pre-rename writer. `docs/MAC-TEST-PLAN.md` now uses `build/ESDaemon` and filters on `process == "ESDaemon"` to match the current binary.

### Fixed
- **The daemons' stderr logs no longer grow without bound.** `reload.sh` installs a `newsyslog` config (`/etc/newsyslog.d/com.esdaemon.conf`) that rotates `/var/log/ESDaemon/eslogger.stderr` and `filter.stderr` by size (1 MB, five archives kept), so the newest lines — the ones that show why a daemon is failing — are preserved while the files stay bounded. Before, launchd appended to them forever: a crash-looping daemon (for example `/usr/bin/eslogger` after Full Disk Access is revoked, which launchd restarts every ~10 s and which writes to stderr on each restart) could fill the disk — a second outage on top of the first. The config is removed by `sudo esdaemon uninstall` and by `./uninstall.sh`; `--purge` deletes `/var/log/ESDaemon` and the rotated archives with it.
- **The installer verifies the `ESDaemon` binary before the daemons run it, and a signing or verification failure stops the install.** `install.sh` hid `codesign` failures (`codesign … 2>/dev/null || true`) and installed a prebuilt `build/ESDaemon` — the one `make build` produces or `quick-install.sh` downloads — with no check that it was signed, intact, or able to run on this Mac. It now ad-hoc signs the writer, runs `codesign --verify --strict` on the result, and checks its architecture (universal, or matching the host) on a staged copy; only a binary that passes is swapped into place (one atomic rename) before the daemons are restarted onto it. If signing, verification, or the architecture check fails, the install stops loudly, leaves the previously installed binary in place, and never restarts the daemons onto an unverified one. The signature stays ad-hoc (`codesign -s -`), not a Developer ID signature, and the binary is not notarized yet; a downloaded release binary's `.sha256` is fetched from the same origin, so it confirms the download is intact in transit, not that it is authentic. README and [docs/GETTING-STARTED.md](docs/GETTING-STARTED.md) say what the install verifies.
- **A pinned `ESDAEMON_REF` install no longer mixes versions.** `quick-install.sh` took its source from `ESDAEMON_REF` (a branch or tag) but always downloaded the prebuilt writer binary from `releases/latest`, so pinning a release (`ESDAEMON_REF=v0.1.0`) paired that tag's scripts and filter with whatever release was newest. The prebuilt binary now comes from the ref's own release (`releases/download/<tag>/ESDaemon-macos-universal`, with its `.sha256` from that same release), so a pinned install is one consistent version. The default unpinned install still tracks the newest release, and a branch — which has no release binary — builds from source (Xcode Command Line Tools) rather than silently taking the newest release's binary. `update.sh`, which pins the latest tag, is unaffected. The download's `.sha256` is still checked for transit integrity, and `install.sh` still verifies the binary's signature and architecture before the daemons run it.
- **Scripts that run as root now pin `PATH` to the system directories.** `install.sh`, `uninstall.sh`, `quick-install.sh`, the `esdaemon` control command, and the `bin/` helpers they run (`reload.sh`, `filter.sh`, `cfg.sh`, `update.sh`, `measure.sh`, `migrate-cfg.sh`, `try.sh`) now set `PATH=/usr/bin:/bin:/usr/sbin:/sbin` before their first external command; the adversary-emulation runner (`redteam/run.sh`) does the same. macOS `sudo` keeps the caller's `PATH` (there is no `secure_path`), so before this a bare tool name — `jq`, `launchctl`, `install`, `curl`, `tar`, `codesign`, `dscl`, `awk` … — resolved through whatever `PATH` the admin's shell had, and anyone who could change that environment could have had their own binary run as root during an install or reload. Defence in depth: the install tree is already required to be root-owned.
- **`measure.sh` tells you its raw capture holds process environments, and how to delete it.** The capture it keeps (`raw.ndjson`, in an owner-only `mktemp -d` directory) is eslogger's output untouched, so every exec event carries the process's full environment, which can hold tokens and other secrets. The closing note now says what the capture contains and prints the exact `rm -rf` to delete it; the capture is kept rather than deleted so `try.sh` can still dry-run an edited config against it ([docs/GETTING-STARTED.md](docs/GETTING-STARTED.md#6-tune-what-is-logged)).
- **A fresh clone's quick start works again.** Every script is committed executable, so `sudo ./quick-install.sh` and `sudo ./uninstall.sh` run from a clone instead of failing with "command not found". `make lint` passes on a copy that lost its execute bits (ZIP download, Windows) and fails if a script is ever committed without the bit again.
- **A clone made on Windows installs on a Mac.** Text files check out with LF line endings on every platform, also under Git for Windows' default `core.autocrlf=true`, so the scripts in a Windows clone, or a ZIP of one, no longer fail on a Mac at `#!/bin/bash\r`. A Windows clone made before this change keeps its CRLF files until it is cloned again. `make lint` fails if a file is ever committed with CRLF line endings.
- **`make lint` fails on what it finds.** A syntax error in any script, not only the last one checked, and any shellcheck finding at warning level or above now fail lint, and with it CI. Before, lint printed them and passed, and reported a shellcheck finding as "shellcheck not installed, skipped". The scripts are now shellcheck-clean.
- **Pipeline no longer aborts on a single odd event.** The per-event state update (not just record building) now runs under a guard, and `procguid` no longer throws on a regex-valid-but-impossible timestamp. Before, one malformed event could kill the filter and lose every event queued behind it. (Found by review; corroborated independently.)
- **A rule that fails on an event no longer hides it.** When an `[include]` / `[exclude]` rule cannot be evaluated on an event, for example a `regex` the regex engine gives up on, run on a long command line the process chose itself, the rule counts as not matching in `[exclude]` and as matching in `[include]`: the event is logged in full, and `esd_rule_error` in its record names the error and the rule. Before, the event's record was replaced by a bare `esd_filter_error` marker, so a process could erase the content of its own records. A record that cannot be built at all still gives that marker, which now names the event (`EventKind`, `User`, `Image`, `ProcessId`) and in the `sysmon` formats carries the Sysmon envelope (EventID 255). See [docs/CONFIG.md](docs/CONFIG.md#writing-safe-rules).
- **argv compute-DoS fixed and the filter made faster.** `CommandLine` is rendered once per exec and reused (was 3×), and `args_max` (default 4096) caps how many argv elements are rendered. A 200k-argument process that stalled the filter ~11 s (dropping real events) now processes in ~0.16 s.
- **Quoting a long argument can no longer stall the filter.** `CommandLine` quotes each argument in time linear in its length, whatever the argument holds, and renders exactly the same string as before. Before, the cost of quoting some arguments grew with the square of their length, so one process could hold up the filter for minutes while macOS dropped the events queued behind it.
- **`eslogger_scoped_gap` points to the right place.** `after_global_seq_num` now reports the sequence the drops followed, not the post-gap sequence.
- **`reload.sh` restart is race-safe.** It waits for each launchd label to be gone before bootstrapping and retries, so a transient launchd error can't leave the filter (or both daemons) stopped with the FIFO undrained.
- **`record_max` clamped to the 32759-byte unified-log ceiling** even at `0`, so an oversize record is always cut to valid JSON instead of being hard-truncated and dropped whole.
- **`ParentImage` is `unknown` for a reparented process whose prior exec wasn't seen**, instead of mislabelling the process's own earlier image as its parent; `launchd_child` no longer treats a `ppid==1` process with no `original_ppid` as launchd-spawned.
- **A `ParentImage is /sbin/launchd` rule matches only a process launchd started.** For rule matching, `ParentImage` reads as `/sbin/launchd` only when launchd is the parent (parent pid 1 from the start), not merely when a parent's most recently seen exec was `/sbin/launchd`. Before, the per-pid exec cache could report `/sbin/launchd` as the parent image of a process whose parent is not pid 1 (or that was reparented to pid 1), so a process could be given that parent image without launchd having started it, and a launch or file event covered by one of the default `ParentImage is /sbin/launchd` excludes (the `xpcproxy` excludes and macOS's own launchd-started daemon excludes) could be dropped. The emitted records are unchanged — the parent image shown is still the one observed, and `ParentProcessId` shows the real parent — and genuine launchd starts are still matched.
- **Self-exclusion hardened**: the `ppid==1` launchd-job heuristic now also requires `euid==0`, so an unprivileged user LaunchAgent can't match it.
- **CI and the release workflow are in the repository.** 0.1.0 listed both, but they never reached GitHub. Every pull request and push to `main` now runs `make lint` and `make test` on Linux and on macOS 15 and 26 (on macOS against Apple's `/usr/bin/jq`), and checks that the `ESDaemon` binary it builds lands a record in the unified log. A `v*` tag that matches `VERSION` publishes the universal binary (`ESDaemon-macos-universal` + `.sha256`) that `quick-install.sh` and `update.sh` install.
- **The installer refuses an install tree other users can change.** `install.sh` and `reload.sh` (and so `esdaemon reload` and updates) stop before they change anything when `/usr/local/ESDaemon`, anything in it, or a directory above it is not owned by root, is group- or world-writable, is a symlink, or (on macOS) carries an ACL that lets another user write, and print each path with the command that fixes it. Before, a user who owned `/usr/local` (older Homebrew installs) could replace what the root daemons run, and ESDaemon logs nothing that runs from its own directory. `esdaemon status` runs the same check, and the same on the `esdaemon` command in `/usr/local/bin`, and exits 1 when one fails, so a directory that changes after the install shows up. The installer no longer resets an existing `/usr/local/bin` to `root:wheel 755`, which took it away from Homebrew, and puts the `esdaemon` command there only when only root can write to it; otherwise run `sudo /usr/local/ESDaemon/bin/esdaemon`.
- **An `xpcproxy` started by hand is logged.** The default excludes for `xpcproxy` with an Apple service name (`com.apple.*`, `application.com.apple.*`) now also require launchd as its parent (parent pid 1 from the start). Before, the service name alone decided, and anyone can give `xpcproxy` that argument, so one started from a shell or script with an Apple service name was dropped. launchd's own launches of Apple services stay excluded, whether they run as root, a service account or the logged-in user, so the default config's volume should not change. A job anyone defines with a `com.apple.` label is started by launchd the same way, so its `xpcproxy` step is still dropped; [docs/DEFAULT-CONFIG.md](docs/DEFAULT-CONFIG.md) says what stays logged.
- **A manual `eslogger` run is logged.** The default exclude for `/usr/bin/eslogger` now also requires launchd as its parent, so it drops only ESDaemon's own continuously-running eslogger daemon (`com.esdaemon.eslogger`), not an `/usr/bin/eslogger` someone runs by hand. Before, every `/usr/bin/eslogger` launch was dropped, hiding a reconnaissance action — reading the endpoint event stream — that a SOC may want to see. The pin is on `ParentImage`, not the command line, so the daemon stays excluded while a manual run from a shell, and a copy of `eslogger` elsewhere, stay logged. The filter's own `eslogger --list-events` is dropped as an ESDaemon process whatever its parent (built in, not this rule); [docs/DEFAULT-CONFIG.md](docs/DEFAULT-CONFIG.md) says what stays logged.
- **The installer checks that this Mac's jq can run the filter.** Before it changes anything, `install.sh` (and so `quick-install.sh` and `esdaemon update --install`) runs the filter on this Mac's `/usr/bin/jq`, with the config it is about to install, over a few sample events; `reload.sh` (`esdaemon reload`) does the same before it restarts the daemons. When jq cannot run it, they stop, change nothing, and print the jq version, what jq said, and the supported floor: macOS 15.0 or later, with the `/usr/bin/jq` that comes with it. Before, the filter daemon was the first to compile the filter: on a jq that rejected it, the daemon restarted every few seconds and collected nothing. README and GETTING-STARTED state the floor and the jq it is tested with (`jq-1.7.1-apple`, macOS 15.7 and 26).
- **`update.sh` reports a missing repository instead of crashing.** With no `VERSION`/`REPO` file beside it (or in the repo root) and `ESDAEMON_REPO` unset, `update.sh` now prints `repository not set: …`, naming where to put the `REPO` file, and exits 1. Before, it aborted under `set -u` with `RFILE: unbound variable`, because the message expanded a path that is only assigned when a `VERSION` file is found.

### Security
- **The collector predicate now requires the event's writer to be root (`userIdentifier == 0`).** ESDaemon's records were selected only by `subsystem == "com.apple.eslogger" AND process == "ESDaemon"`, but neither field is protected: any user can run a program named `ESDaemon` that logs under that subsystem, so a non-root process could inject records a collector would ship as ESDaemon's. The real filter always runs as root, so the predicate now adds `AND userIdentifier == 0` — a value the unified log takes from the logging process's uid, which no unprivileged process can forge. **If you already run a collector, update its predicate** to `subsystem == "com.apple.eslogger" AND process == "ESDaemon" AND userIdentifier == 0` (keep `AND category == "events"` if you filter on category). `esdaemon logs`, the watch commands in the README and [docs/GETTING-STARTED.md](docs/GETTING-STARTED.md#5-ship-the-events-to-your-siem), the install scripts, and CI already use the hardened predicate.

## [0.1.0] — first public release

### Added
- `eslogger` → filter → unified log pipeline as two LaunchDaemons (`com.esdaemon.eslogger`, `com.esdaemon.filter`) connected by a FIFO; records go to subsystem `com.apple.eslogger`, category `events`, process `ESDaemon`.
- `[modules]`: choose what to log as `<object> = <operation>`: `process` (`start`, `exit`, `inject`), `file` (`read`, `write`, `create`, `delete`, `rename`, `attributes`), `user` (`login`, `logout`, `sudo`, `account`), `system` (`persistence`, `malware`, `kernel`, `mount`). `file = read` logs read-only opens; `file = write` logs a changed file once, when it is closed.
- `[include]` / `[exclude]` with Sysmon's filter semantics and vocabulary (`is`, `contains`, `begin with`, `image`, `regex` … and their negations); exclude always wins. Fields: `EventType`, `Image`, `CommandLine`, `CurrentDirectory`, `ParentImage`, `ParentCommandLine`, `User`, `TeamId`, `SigningId`, `IsPlatformBinary`, `TargetFilename`. On file and other events `ParentImage` is the parent of the acting process, so "a tool and everything it launches" covers the files they write.
- Sysmon-style records with a fixed field order: `EventID`, `EventType`, `UtcTime`, `User`, `Image`, `CommandLine`, …, `ProcessGuid` / `ParentProcessGuid` (GUID-shaped, linkable), code signing last. Output formats `sysmon`, `sysmon+extras` (default), `slim`, `raw`.
- Default config: `process = start`, `file = create, delete`, `user = login`, and excludes for collector self-noise and Apple housekeeping: Apple `xpcproxy`, Spotlight, temp copies of Apple daemons, and macOS's own launchd-started daemons (their starts and their private files); see [docs/DEFAULT-CONFIG.md](docs/DEFAULT-CONFIG.md).
- `ParentImage` is `/sbin/launchd` for anything launchd started (parent pid 1 from the start, also without having seen the parent); conditions `begin with any` / `end with any`.
- ESDaemon never logs its own processes (its binaries and the processes its launchd job starts); admin runs of `reload.sh` / `install.sh` are logged.
- Config validation before anything runs (`cfg.sh`): unknown sections, settings, modules, rule fields or conditions, bad regexes and empty values are errors; `reload.sh` and `install.sh` change nothing on an invalid config.
- Records kept under the unified log's 32 KB limit (`record_max`): the largest value is cut in the middle, marked `…[+N chars]…`; `ParentCommandLine` capped by `parent_cmdline_max`.
- Drop and restart markers (`eslogger_scoped_gap`, `eslogger_scoped_restart`) so lost events are visible.
- `quick-install.sh` (fetch, verified prebuilt binary or build, install, check), standalone `uninstall.sh` (`--purge`), `update.sh` (compare with the latest GitHub release; `--install` to update), `install.sh` that keeps a tuned config and migrates older ones (`migrate-cfg.sh`).
- `measure.sh` (volume per source), `try.sh` (dry-run a config on a capture), MDM PPPC profile for eslogger's Full Disk Access, CI on Linux and macOS, release workflow with a universal binary.
